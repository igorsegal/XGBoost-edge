# Реестр правил XGBoost-edge

Один файл `rules_registry.json` хранит все правила. Тестер берёт из него значения параметров по умолчанию, а конфиг теста (`configs\*.json`) включает нужные правила и переопределяет параметры.

## Как пользоваться
- Запустить все тесты разработки: двойной щелчок по `RUN_TESTS.bat` (компиляция, проверка реестра, прогон всех конфигов с проверкой причинности, запись результатов в реестр). Экзамен этот файл не открывает.
- Открыть экзамен для одного основного теста: `tester\tester.exe configs\ИМЯ.json --selftest --exam`, затем `python record_results.py`. Правила экзамена: `SVOD_PRAVIL.md`.
- Включить или выключить правило для теста: в конфиге `"rules": {"ID": {"enabled": true}}`.
- Изменить параметр только для теста: в конфиге `"params": {"имя": значение}` (значение проверяется по диапазону из реестра). Значения по умолчанию в реестре не меняются.
- Новое правило: `python add_rule.py НОВЫЙ_ID "Название"`, заполнить запись в реестре, `python validate_registry.py`. Если правило нельзя записать строкой условия (веса, обучение внутри правила), добавить файл `tester\rules\<имя>.h` и одну строку в `factories()` в `tester\tester.cpp`.
- Проверить реестр и конфиги: `python validate_registry.py`.
- Занести результаты в реестр: `python record_results.py`.

## Правила без кода: inputs и строка условия (с версии реестра 2)
Правило, которое сводится к «индикатор сравнивается с числом или с другим индикатором», записывается прямо в реестре, код на C++ не нужен: `implementation: {"kind": "expr"}`.
- `inputs` - список нужных индикаторов: `{"name": "rsi", "indicator": "RSI", "tf": "H4", "source": "close", "params": {"period": "$rsi_period"}}`. `tf` по умолчанию равен таймфрейму теста; старший таймфрейм берётся по последнему ЗАКРЫТОМУ бару. `"$имя"` - ссылка на параметр правила, поэтому период можно менять в конфиге теста.
- `entry_long_expr`, `entry_short_expr` - условия строкой. Можно: имена входов, имена параметров, цены (`open high low close spread`), числа, `+ - * /`, `< <= > >= == !=`, `AND OR NOT`, скобки, функции `abs(x) min(a,b) max(a,b) prev(x,n) crossup(a,b) crossdown(a,b)`. Цепочки `a < b < c` не поддерживаются: писать `a < b AND b < c`. Если ряд ещё не прогрет (NaN), условие не считается выполненным. Если сработали оба условия, сигнала нет.
- Список индикаторов, их параметров, диапазонов и формул: `indicators_catalog.json`. Реализованы все 55: скользящие (SMA, EMA, WMA, HMA), осцилляторы (RSI, STOCH, CCI, ROC, WILLR, MFI, MOMENTUM, CMO, ULTIMATE, TSI, MACD), волатильность (ATR, BBANDS, KELTNER, DONCHIAN, STDDEV, PARKINSON, GARMAN_KLASS), тренд (ADX, AROON, PSAR, SUPERTREND, ICHIMOKU, VORTEX, LINREG), объём (OBV, OBV_SLOPE, VOLRATIO, CMF, AD, VWAP_SESSION, FORCE, EOM), свечи (BODY_RATIO, UPPER_SHADOW, LOWER_SHADOW, GAP, INSIDE_BAR, OUTSIDE_BAR, ENGULFING, PINBAR, DOJI), структура (HIGHEST, LOWEST, PIVOT_DAY, PIVOT_WEEK), время (HOUR, WEEKDAY, SESSION, MINUTE_OF_HOUR, BAR_OF_DAY). Индикатор со статусом `planned` в правило вписать нельзя. Объёмы - тиковые из файла истории; время - из файла истории.
- Параметры индикаторов можно менять в тесте без пересчёта чего-либо вручную: тестер считает индикатор из свечей с любым значением в пределах диапазона из справочника.
- Образец формата: правило `EXAMPLE_RSI_PULLBACK_01` (статус `example`, в результаты реестра не заносится). Новое правило: `python add_rule.py НОВЫЙ_ID "Название" --expr`.
- Новый индикатор: добавить запись в `indicators_catalog.json`, формулу в `tester\indicators.h` и случай в `tests\xcheck_indicators2.py` (независимый расчёт), статус `implemented` только после совпадения.

## Стратегии со своими выходами
`implementation: {"kind": "strategy"}`: правило само задаёт вход, стоп, цель и безубыток (модуль в `tester\rules\`), в конфиге `"exits": {"by_rule": true}`. Полный текст правил и допущений: `specs\<ID>.md`. `--selftest` портит будущие свечи всех используемых таймфреймов вместе со спредом; `--trades=файл.csv` выгружает сделки разработки. Независимые проверки (сверка сделка за сделкой): `tests\xcheck_london.py` для `LONDON_TRAP_01`, `tests\xcheck_classic.py` для `CLASSIC_TRACE_01`, `tests\xcheck_ny.py` (с общим `xcheck_levels.py`) для `NY_CONTINUATION_01`.

## Проверки
- `tests\xcheck_indicators.py` и `tests\xcheck_indicators2.py`: каждый индикатор пересчитывается заново на Python (время считается библиотекой datetime) и сравнивается с тестером по каждому бару.
- `tests\xcheck_expr_example.py`: сигналы и сделки правила-примера пересчитываются на Python и сравниваются с тестером по разработке и каждому окну. То же для Hedge: `tests\xcheck_hedge.py`.
- `--selftest` тестера: для 8 точек среза портятся все бары, закрывающиеся после среза; значения индикаторов и сигналы до среза не должны измениться.

## Статусы правил
`spec_ready` (описано), `implemented_untested` (реализовано, не проверено), `dev_pass` (прошло разработку, экзамен не сдан), `tested_pass`, `tested_fail`, `prototype_unconfirmed` (из прототипа, не подтверждено), `rejected`, `example` (учебный образец формата).

## Критерии и деление времени
Действует `SVOD_PRAVIL.md`. Скользящие окна: обучение 6 месяцев, проверка 2, сдвиг 2; разработка 2020–2024, закрытый экзамен с января 2025. Принято, если по сумме проверочных кусков и на разработке, и на экзамене нетто после издержек больше нуля, профит-фактор не ниже 1,3 и сделок не меньше 100. Выход через 24 бара, стоп 2×ATR(14). Издержки: спред из бара плюс комиссия 7 USD за лот (лот золота 100 унций). Правила с заданными параметрами на обучающих месяцах ничего не подбирают: тестер считает их только на проверочных.

## Облачная сборка и тесты

`.github/workflows/cloud_tests.yml` запускается на GitHub после отправки изменений в `registry/cloud`,
`registry/configs` или `registry/tester` (или вручную во вкладке Actions). Облако само скачивает котировки из
открытых наборов, собирает бары, сверяет их с паспортом локальной базы (`cloud/bars_manifest.json`),
проверяет реестр и индикаторы, прогоняет тесты разработки и сверяет их с локальными результатами.
Отчёт: `reports/cloud_tests.md`. Экзамен в облаке не открывается. Котировки в репозиторий не выкладываются.

После пересборки локальной базы: `python cloud/make_manifest.py D:\AHexaTrader\1DataFiles\BAZA cloud/bars_manifest.json`.
